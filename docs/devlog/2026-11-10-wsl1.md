## Found on the way

- With batond running, `baton status`, `baton doctor` and plain `sqlite3` all failed with
  `locking protocol`: WAL's shared memory (`baton.db-shm`) is not shared across processes
  on WSL1. The ledger now uses the rollback journal there; the store tests, including a
  second process reading the log batond holds open, pass on WSL1.
- A real Claude Code task on WSL1 (add `power(a, b)` with a test) ran to `completed`
  through `baton task add` and batond, started by a Windows scheduled task.

- WSL1 kills every process of the distribution when the last `wsl.exe` attached to it
  exits: `nohup` and `setsid` from an SSH session do not survive. batond and herdr need a
  `wsl.exe` that stays.
- `wsl --install` re-enables VirtualMachinePlatform on every run and asks for a reboot
  before registering the distribution; `wsl --import` of the image from Microsoft's
  distribution list (SHA-256 checked) avoids the loop.
- The `resolv.conf` WSL1 generated held unreachable `fec0::` servers; `generateResolvConf`
  is off and the router, Tailscale and 1.1.1.1 are set by hand.
